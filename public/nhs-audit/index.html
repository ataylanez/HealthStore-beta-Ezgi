NHS HealthStore — design audit

NHS layout and typography audit

How far the NHS HealthStore prototype had drifted from the NHS design system's page layouts and typography, what we changed to bring it back, and what is still left to decide.

Who this is for. UX and interaction designers working on the HealthStore. It is written in plain language; the technical detail lives in the code and in docs/NHS_DESIGN_SYSTEM_MIGRATION.md.

What we checked against. NHS Frontend version 9.6 (the NHS design system's code), with GOV.UK Frontend only where NHS has no equivalent component. Every "NHS expects" statement below was verified against the NHS Frontend source, not from memory.

Date. 16 October 2026. Screenshots were taken at 1280px (desktop) and 375px (mobile).

Summary

The site looked NHS-like at a glance (blue header, Frutiger, NHS buttons and form fields) but underneath it was running its own layout system. Pages were 1280px wide instead of the NHS 960px, almost nothing used the NHS grid, and headings, intro text and labels were styled by hand rather than with the NHS type styles. The result was long reading lines, inconsistent spacing between pages, and a lot of small grey text that NHS content would set at body size.

We found 19 distinct deviations across six themes. 16 are fixed in this iteration, including everything we rated highest priority; 2 are partly fixed (what remains is structural or a content review); and 1 group of bespoke components needs a decision from you (listed at the end).

The headline changes:

  • Every page now sits in the NHS 960px width container with NHS vertical spacing. The header, navigation and "Alpha" banner follow the same width.
  • Reading content, forms and journeys sit in an NHS two-thirds column. Product pages and the catalogue use the NHS one-third / two-thirds layout.
  • All page titles, section headings, intro text and lists use NHS type styles. Capitalised, letter-spaced labels and sub-16px text are gone.
  • The home page uses the NHS hero component and NHS card groups.

The NHS type sizes themselves were already correct in our design tokens. The problem was how text was applied, not the scale.

What the NHS design system expects

A short, non-technical version of the rules we measured ourselves against.

Page width
Content lives in a container no wider than 960px, centred, with 16px side margins on small screens and 32px on larger ones. The header, navigation and footer share the same width.
Vertical rhythm
The main area has 24px of padding top and bottom on mobile and 48px on desktop (or 16/24px when a breadcrumb or back link sits above it). Spacing uses the NHS points scale: 4, 8, 16, 24, 32, 40, 48, 56, 64px.
Grid
A simple row of columns: two-thirds for reading content and forms, one-third for a contents list or filters, one-half and one-third for cards. Columns stack on mobile.
Reading width
Body text should never run across the full 960px. Two-thirds (about 613px) is the standard reading column.
Type scale
Desktop: 64, 48, 36, 26, 22, 19, 16, 14px. Mobile: 48, 32, 27, 22, 19, 16, 14, 12px. Body text is 19px on desktop and 16px on mobile. Nothing below "body small" (16/14) is used for content.
Headings
Page title is heading XL (48px), major sections heading L (36px), sub-sections heading M (26px) and heading S (22px). Headings are bold (weight 600 in Frutiger) and sentence case. Each heading style carries its own top and bottom spacing, which is what gives NHS pages their consistent rhythm.
Intro text
A page's opening paragraph uses lede text: 22px on desktop, 19px on mobile (the older 24px lede was retired).
Labels and captions
Sentence case, normal letter spacing, body-small size at minimum. NHS never uses UPPERCASE letter-spaced labels.
Links
Underlined at rest, blue, and they change colour (not just gain an underline) on hover.
Standard components
Hero, card and card group, contents list, summary list, inset text, breadcrumb, back link, pagination, details. These should be used in place of bespoke equivalents wherever they fit.

Findings: where we were different

Grouped into six themes. Each one states what NHS expects, what we had, why it matters to users, and what we did. Priority reflects how many pages were affected and how visible the problem was: P1 systemic, affects every page; P2 affects a whole page type; P3 local polish.

Theme A — The page frame

A1. Pages were 1280px wide, not 960px

P1 Done
NHS expects
A 960px container, shared by header, navigation, banner and content.
What we had
Our own page wrapper at 1280px on 51 pages, and the header, navigation and "Alpha" banner forced wider still (1280px) with their own overrides. The NHS container was used once, for the footer.
Why it matters
Lines of text ran far past a comfortable reading length, every component looked smaller than it does on nhs.uk, and the site felt wider than any NHS service people are used to.
What we did
Moved every page onto the NHS width container. Removed the header, navigation and banner width overrides so the whole frame is 960px.

A2. Vertical spacing came from our wrapper, not the NHS main wrapper

P1 Done
NHS expects
24px / 48px padding around the main area; 16px / 24px when a breadcrumb sits above it. The footer follows immediately.
What we had
Our wrapper used 32px / 40px, plus an extra 64px gap pushed in above the footer. Several pages then added their own off-scale gaps (72px, 96px, 20px, 1.25rem).
Why it matters
Page-to-page spacing was inconsistent: the title sat at a different height on the home page, the catalogue and a product page.
What we did
Adopted the NHS main wrapper (and its "small" variant below breadcrumbs) everywhere. Removed the footer gap and the off-scale values.

A3. Breadcrumbs sat inside the padded content area

P2 Partly done
NHS expects
The breadcrumb sits between the header and the main wrapper, then the main wrapper uses its smaller padding.
What we had
Breadcrumbs inside the page padding, so the gap above them varied by page.
What we did
On every shared page frame (product pages, guidance articles, catalogue, funding, resources, cookies, about) the breadcrumb now sits above the main wrapper exactly as NHS lays it out. On the remaining individual pages we pull the breadcrumb up to the same visual position. The one thing left is purely structural: the breadcrumb is still technically inside the <main> landmark. It looks identical; see "Left for a future iteration".

Theme B — The grid and reading width

B1. The NHS grid was barely used

P1 Done
NHS expects
Rows of one-third / two-thirds / one-half columns.
What we had
The NHS grid appeared in one file. Everything else used ad-hoc widths: "max-w-2xl", "max-w-3xl", "max-w-[640px]", a 14rem sidebar, a self-filling card grid.
Why it matters
Reading widths differed between the EOI form, the supplier portal and guidance articles even though they are all "one column of content". Nothing lined up across pages.
What we did
Forms, journeys, articles, the funding index, cookies, about and the 404 page now use a two-thirds column. Product pages and the catalogue use one-third + two-thirds. Card rows use NHS card groups in one-third or one-half columns.

B2. Body text ran across the full page width

P1 Done
NHS expects
Paragraphs in a two-thirds column (about 613px).
What we had
Intro text on the compare, catalogue, resources and portal pages ran the full 1280px; some pages capped it with our own "measure" class instead of a grid column.
What we did
Intro text and paragraphs now live inside two-thirds columns. The custom measure class is now only an alias for the same width.

Theme C — Headings and intro text

C1. Page titles and section headings were styled by hand

P1 Done
NHS expects
heading-xl for page titles, heading-l / -m / -s for sections, each with built-in spacing.
What we had
40 page titles used a custom "page-title-h1" style; product page sections, home page bands and the funding index each had their own heading styles with their own spacing (and some inline styles). Sizes were right, spacing wasn't.
Why it matters
The gap between a heading and the content under it, and between a list and the next heading, varied from page to page. This is the single most noticeable "not quite NHS" feeling.
What we did
All page titles are heading-xl; product section titles are heading-l; sub-sections heading-s; home page bands heading-l; cookies and about page sections heading-m. Custom heading styles were removed.

C2. Intro text used the retired 24px lede

P2 Done
NHS expects
Lede text at 22px desktop / 19px mobile (nhsuk-lede-text).
What we had
A 24px lede token (the pre-v9 size) and, on many pages, a plain grey body-size paragraph doing the lede's job.
What we did
The lede token now matches NHS 22/26. Page intros use nhsuk-lede-text (resources, guidance, funding, cookies, about) or nhsuk-body-l where the intro is more of a description (portal, compare).

C3. The product page title had no supplier caption

P3 Done
NHS expects
Context above a title uses a caption inside the heading (nhsuk-caption-xl).
What we had
Supplier name as a separate small line.
What we did
Supplier name is now an NHS caption inside the product title, on both the overview and section pages.

Theme D — Labels, small text and weights

D1. Uppercase, letter-spaced labels

P1 Done
NHS expects
Sentence case labels at body-small size, no tracking.
What we had
22 places used UPPERCASE with wide letter spacing (product detail tables, funding results, "what it's worth" tiles, how-to-buy, supplier contact card, pathway headings, before/after chart tiles).
Why it matters
It is the most visible GOV.UK/marketing-site idiom on the page and reads as "not NHS" immediately. Uppercase is also harder to read for people with dyslexia.
What we did
All removed. Labels are sentence case, bold where they need weight, at body-small size.

D2. Small text doing the job of body text

P2 Partly done
NHS expects
Running copy at body size (19/16). Body-small (16/14) only for genuine metadata.
What we had
Our "label" size (16/14) was used about 115 times, often for whole paragraphs — most heavily in the product detail sections, AI advisor panels, funding levers and the compare snapshot.
What we did
Promoted the running copy to body size in the heaviest files: product detail sections, funding levers, commissioning snapshot, AI chat and advisor panels, compare snapshot (which also used a 12px size — below the NHS minimum). About 105 genuine labels, table cells and metadata remain at body-small, which is correct; a line-by-line content review would decide the few borderline cases.

D3. Fixed pixel sizes off the NHS scale

P2 Done
NHS expects
Only sizes from the type scale; 14px is the floor on desktop.
What we had
12px home-page pills, 12px / 14px scenario controls, 11px / 13px chart labels, a 12px navigation count, a 14px snapshot heading.
What we did
All moved to NHS body-small or the badge size (which is already on scale).

D4. Font weights NHS doesn't use

P3 Done
NHS expects
Regular (400) and bold (600) only.
What we had
A weight-500 "medium" in scenario controls, and a Frutiger Light (300) font file loaded but never used.
What we did
Removed both.

D5. Links underlined only on hover

P3 Done
NHS expects
Links underlined at rest.
What we had
The product "on this page" navigation and nine components (detail links, supplier email, concept cards, AI wizard back links, cookie banner "view cookies") gained their underline only on hover.
What we did
Underlined at rest; the underline lifts on hover, as NHS does. The product navigation is now the NHS contents list.

Theme E — Page layouts

E1. Home page used a bespoke full-bleed layout

P2 Done
NHS expects
The NHS hero (blue band, title, lede, optional image) followed by content in the width container, cards in NHS card groups.
What we had
A custom hero at 1280px, storytelling bands that bled edge to edge, and card rows on a Tailwind grid.
What we did
Hero is now the NHS hero with the illustration in a one-third column; "What the HealthStore addresses", "How it works", "Conditions and pathways" and "Case studies" sit inside the width container with NHS card groups. All content and imagery was kept.

E2. Product pages had a custom sidebar that disappeared on mobile

P2 Done
NHS expects
A one-third contents list beside a two-thirds content column; the contents list stacks above the content on mobile.
What we had
A 14rem sticky sidebar in a custom grid, hidden entirely under 1024px, content capped at 640px, section titles with 72px gaps, metric tiles on a Tailwind grid.
What we did
NHS contents list in a one-third column (visible on mobile), content in two-thirds, tiles on NHS one-third/one-half columns, "How to buy" and "Regulatory position" as NHS summary lists, callouts as NHS inset text.

E3. Catalogue used a GOV.UK-style filter panel and a self-filling card grid

P2 Done
NHS expects
Filters in a one-third column, results in two-thirds as a list of cards; a product count as text, not a heading.
What we had
A collapsible filter panel above an auto-fill grid; the result count was an <h2>.
What we did
One-third filters (collapsible on mobile, always open on desktop) beside a two-thirds stacked list of NHS cards. Count is body text. The discovery page and resources index use NHS card groups.

E4. Forms and journeys used arbitrary max-widths

P2 Done
NHS expects
Forms in a two-thirds column; button groups spaced with NHS points.
What we had
Express-interest steps, supplier onboarding and supplier portal pages each wrapped in "max-w-2xl" / "max-w-3xl" (672 / 768px); a 96px gap above some button rows; a hand-styled blue notice panel.
What we did
Two-thirds column across all 32 journey and portal pages; 40px NHS spacing above button rows; the notice is NHS inset text; portal dashboard tiles are an NHS card group.

E5. Resource pages set their own widths and heading styles

P2 Done
NHS expects
Article in a two-thirds column with heading-xl; section indexes as lede plus a list.
What we had
Articles capped at 40rem inline; section indexes with hand-styled grey intros and bold 19px links; the resources index on a Tailwind card grid.
What we did
Articles in two-thirds; indexes use lede text and an NHS bulleted list of links; the resources index is an NHS card group of secondary cards.

Theme F — Bespoke chrome with no NHS pattern

F1. Floating "back to top" button, AI Advisor drawer, compare count badge, GOV.UK-styled tags

P3 Needs decision
NHS expects
NHS has no floating action button, drawer or badge pattern. Its tag has its own look (coloured background, no border radius).
What we had
All four are bespoke and working. The tag has been restyled to look like the GOV.UK tag.
What we did
Nothing yet. Each is a product decision, not a styling fix — see "Needs your decision".

Left for a future iteration

Safe, well-understood changes that we did not make now because they are either invisible, add new behaviour, or are clean-up rather than alignment.

  1. Breadcrumb outside <main>. Visually it is in the right place. Structurally the NHS template puts the breadcrumb before the main landmark, which helps screen-reader users skip straight to content. Needs a small change to how pages hand their breadcrumb to the shell.
  2. NHS pagination. The catalogue shows all products on one page and resource articles have no previous/next links. A pagination component already exists in the codebase but is unused. Adding it is new behaviour, so it should be designed, not just switched on.
  3. Remaining body-small text. About 105 uses remain, nearly all genuine labels, table cells and metadata. A content pass would catch the few that should be body size.
  4. Unused code. A pathway illustration component with 10–13px SVG text is no longer used; a handful of custom CSS classes (section title, card grid, pathway button) have no consumers; and there are duplicate files named "… 2.tsx" / "… 2.md" in the repository that are not imported. All candidates for deletion.
  5. The legacy page wrapper class. Our old wrapper class now simply mirrors the NHS container and nothing in the pages references it any more; it can be deleted from the stylesheet.

Needs your decision before we act

These are product or design choices rather than alignment fixes. We have described the trade-off and a recommendation for each.

1. Comparison tables at 960px

Four products side by side was designed for a 1280px page. At 960px the table columns are tighter and rely on the responsive stacking that already exists for mobile. Options: (a) accept it and tune the column content, (b) cap comparison at three products, (c) grant the compare page a documented exception to go wider. Recommendation: try (a) with real content first; NHS services generally do not make width exceptions.

2. Floating "back to top" button

NHS has no floating action button pattern; long NHS pages use the contents list and a "back to top" link inline at the end of sections. Options: keep the button (familiar, works), or replace with inline links. Recommendation: replace with inline "Back to top" links under each long product section now that the contents list exists.

3. AI Advisor drawer

A slide-out panel with its own typography and spacing. There is no NHS pattern for a chat drawer; the nearest is a full page or a card. Options: keep as a documented bespoke component but restyle its internals to NHS type and spacing (largely done in this iteration), or move the advisor to its own page. Recommendation: keep the drawer for the prototype; restyle is sufficient for now.

4. Compare count badge

A small count bubble in the navigation. NHS has no badge pattern. Options: keep, or show the count as text in the link label ("Comparison tool (2)"). Recommendation: text in the label — simpler, accessible, and NHS-like.

5. Tag styling

The NHS tag has been restyled to look like the GOV.UK tag (bordered, grey-blue). The native NHS tag is a solid colour chip. Options: revert to the NHS look, or keep the GOV.UK look as a deliberate gap-fill. Recommendation: revert to the NHS tag; it is an NHS component, so there is no gap to fill.

What was already right

Worth saying, so nobody re-litigates it:

  • The type scale. Our size tokens exactly matched NHS Frontend v9 (64/48/36/26/22/19/16/14 desktop; 48/32/27/22/19/16/14/12 mobile) and NHS bold is weight 600, which we used. The deviations were in how text was applied, not the sizes.
  • Forms. Inputs, radios, checkboxes, error summaries, buttons, back links and the check-your-answers summary lists already used NHS components.
  • Header, footer, breadcrumb. NHS components throughout; only their width was wrong.
  • Colour. NHS palette, including the recolouring of the GOV.UK gap-fill components (cookie banner, accordion, phase banner).
