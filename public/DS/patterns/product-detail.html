Product detail (PDP)

A product is a small NHS-style content hub: an overview page plus one page per section, all sharing a one-third contents list and a two-thirds reading column. Since Round 10 it is laid out entirely with NHS primitives — width container, grid, contents list, heading-xl with caption, summary lists and inset text.

What changed in Round 10. The custom sticky “On this page” sidebar, the 640px main column, the nhsuk-tabs block and the Save / Share utility cluster are gone. Each former tab is now its own page under /apps/[slug]/[section]. See Archived.

Anatomy

  1. Breadcrumb — Home / Product catalogue / [product] (on section pages: … / [product] / [section]). Sits inside the width container, above the main wrapper.
  2. Frame (PdpFrame) — nhsuk-width-container → nhsuk-main-wrapper--s → nhsuk-grid-row with a one-third aside and a two-thirds main column. The aside stacks above the content on mobile.
  3. Section navigation (PdpSectionNav) — an NHS nhsuk-contents-list of the product’s pages. The current page is plain bold text (nhsuk-contents-list__current), not a link.
  4. Title — nhsuk-heading-xl with the supplier as a nhsuk-caption-xl inside the h1, then the value proposition as nhsuk-lede-text, then condition / maturity / supervision tags.
  5. Actions — CompareToggleButton (solid button, pressed state) next to the title; the Express interest callout (PdpExpressInterestCallout) at the end of the column.
  6. Commissioning snapshot (PdpCommissioningSnapshot) — a compact summary of cost, evidence, where it is live and funding; each segment links to the relevant section page.
  7. Overview summaries (PdpOverviewSummary) — one nhsuk-heading-l block per section with a short summary (bullets, inset text or a sentence) and a “Read more about…” link to the section page.
  8. Section pages — the problem → how it helps → projected impact → local value → funding levers → assurance → implementation → NHS experience → how to buy → resources. Each page renders one component (PdpProblem, PdpHowItHelps, PdpLocalValue, PdpFundingLevers, PdpAssurancePassport, PdpImplementation, PdpNhsExperience, PdpHowToBuy, PdpResources).
  9. Share & print (PdpSharePrintContext) — regions are tagged so a shared link can show a subset of the page; the UI is a plain NHS button row, not a cluster.

Section pages

Every section lives at /apps/[slug]/[section] and uses the same frame, so the contents list never moves. The section heading is an nhsuk-heading-l (.hs-pdp-heading adds only the anchor offset). Titles come from one place, lib/pdpSections.ts, so the nav label and the on-page heading can never drift apart.

Commissioning snapshot

Still a bespoke strip (.hs-snapshot-strip__*) because NHS has no equivalent; it uses NHS points for padding (16/24) and nhsuk-body-s for labels. Four equal segments keep width stable even when funding is absent. Each segment is a link to its section page.

2 opportunities

Do

  • Keep the contents list to the product’s own pages; link out to the catalogue via the breadcrumb.
  • Give each section page one nhsuk-heading-l and keep the h1 for the product name.
  • Use nhsuk-summary-list for key/value facts and nhsuk-inset-text for caveats.

Don't

  • Reintroduce tabs, sticky sidebars or a secondary action cluster in the title area.
  • Constrain the main column below the NHS two-thirds width.
  • Hide the section navigation on mobile — it stacks above the content.
