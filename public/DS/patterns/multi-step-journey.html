Multi-step journey

The GOV.UK "question pages" pattern built from NHS components: one question per page, a working back link on every step, error summary on validation failure, a Check your answers page, and a green confirmation panel. Used by the Express interest journey on PDPs and, as a second instance, by supplier onboarding and the supplier portal editors. Every step renders in a nhsuk-grid-column-two-thirds column.

GOV.UK pattern, NHS components

Step order (Express interest)

  1. Start — h1, nhsuk-inset-text ("not a purchase or procurement award"), Continue.
  2. Your details — FormField text inputs; required fields validated on Continue.
  3. Verify your email — interstitial with a prototype one-time code (123456) before the questions continue.
  4. What support do you need? — nhsuk-checkboxes in a fieldset whose legend is the page h1.
  5. Timing and context — nhsuk-radios for timeline plus optional inputs; all optional.
  6. Check your answers — nhsuk-summary-list with Change links back to each question; submits the expression of interest.
  7. Confirmation — nhsuk-panel plus "What happens next" and onward links.

Rules

  • One thing per page. The question is the <h1> (or the fieldset legend contains it).
  • Every step has a working back control that preserves answers; the first step's back link returns to the entry page (the PDP).
  • Validation runs on Continue. Failures render an nhsuk-error-summary (focused) plus per-field nhsuk-error-message.
  • Changing an answer from Check your answers returns the user to Check your answers afterwards, not the next step.
  • On step change, scroll to top and focus the heading so screen readers announce the new question.
  • Optional answers play back as "Not provided" on Check your answers.
  • Each step is its own route so the browser back button and refresh behave; answers persist in session state between routes.
  • Buttons use the NHS button (components/ui/Button.tsx); button groups are spaced with nhsuk-u-margin-*.

  • Error summary
