Loading & skeletons

Placeholder UI shown while content loads (catalogue, comparison and supplier portal routes use Suspense skeletons). A skeleton reproduces the same NHS layout as the page it stands in for — width container, main wrapper, grid columns — so nothing moves when data arrives. Shimmer respects reduced-motion.

Components
CatalogueSkeleton, CompareSkeleton, PortalSkeletonPage
Semantics
role="status" aria-busy="true" on the wrapper, visually hidden “Loading…” text, skeleton shapes aria-hidden

Catalogue skeleton (one-third / two-thirds)

Mirrors the product list: a filter-panel block in the one-third column and stacked card shapes in the two-thirds column.

Line skeletons

Guidance

  • Match the skeleton to the real content's layout to avoid shift on load.
  • Use skeletons for first loads; use inline spinners/aria-busy for in-place updates (e.g. Save toggle).
  • Keep shimmer subtle; it disables under prefers-reduced-motion.

Accessibility

  • Wrap loading regions in an aria-busy="true" container, or announce status via an aria-live region.
  • Skeleton shapes are decorative and should not be announced individually.
