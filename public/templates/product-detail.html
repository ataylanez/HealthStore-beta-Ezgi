Templates · T6

Product detail page

A small set of pages for one product: an overview and one page per section, sharing a contents list and a two-thirds reading column. Rendered from a structured product record plus CMS-edited narrative.

Pages using this template

RouteH1Notes
/apps/[slug]Product name, with the supplier as a caption inside the titleOverview: short summary of each section, plus links into the section pages
/apps/[slug]/[section]The section heading (the product name stays in the contents list)One page each for: the problem, how it helps, local impact, what it could be worth, funding levers, assurance, implementation, NHS experience, how to buy, resources

Structure and content regions

Both the overview and the section pages use the same frame, so the contents list does not move as you go from page to page.

RegionContentWho edits
BreadcrumbHome, catalogue, product. On a section page, the section is the current page and is left off the trail. Sits above the main area.Automatic
Contents listOne-third column. NHS contents list of the overview and the sections. The current page is bold text; the others are links. Labels come from the same list as the section headings.Automatic
TitleTwo-thirds column. Extra-large heading. The supplier name is a caption inside the heading, then the value proposition as lede text, then condition and maturity tags, and Add to compare.Product record CMS editor (value proposition)
Commissioning snapshotA short strip of cost, evidence, where it is live, and funding. Each part links to the matching section page.Product record
Overview summariesOn the overview only: one block per section, with a short summary and a “read more” link to that section’s page.Product record CMS editor
Section bodyOn a section page: the full narrative for that section (prose, lists, summary lists, tables, or the local-value model).Product record CMS editor
Local value and projected impactCohort and worth modelling on the local-impact and local-value pages.Site functionality (model and reference data)
Express-interest calloutAt the foot of the column. Call to action into the EOI journey (T7).Site functionality

Notes

Wagtail consideration note: Products should be a first-class Wagtail page type with typed fields and a child page (or routable section) per narrative section, replacing today’s content/apps/*.json files. Section titles live in one place (lib/pdpSections.ts today) so the contents list and the on-page headings stay in step. The local-value modelling, compare and express-interest actions are site functionality layered onto the page, not CMS content.
